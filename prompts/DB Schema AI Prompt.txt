====================================================
ANALYSIS RULES
====================================================


1. FIELD LEVEL ANALYSIS

Every database column must be analyzed.

For every field identify:

- Technical purpose
- Business meaning
- Feature relevance
- User impact


Example:

Database Field:

ISENCASHABLE


Technical:

Boolean configuration field


Business Meaning:

Controls whether unused leave can be converted into monetary benefit.


Feature:

Leave Encashment


User Impact:

Employee may receive payment for unused leave.


----------------------------------------------------


2. IDENTIFY ERP DESIGN PATTERNS

Identify:

- Master data
- Transaction header
- Transaction details
- Configuration tables
- Reference tables
- Status management
- Audit tracking
- Formula-based processing
- Multi organization support
- Multi tenant architecture


----------------------------------------------------


3. EXTRACT MAXIMUM INTELLIGENCE

Identify:

- Product features
- Automation capability
- Workflow capability
- Approval capability
- Calculation capability
- Tracking capability
- Reporting capability
- Integration possibilities


----------------------------------------------------


4. BUSINESS RULE EXTRACTION

Extract rules from:

- Default values
- Constraints
- Status fields
- Boolean fields
- Formula references
- Date fields
- Calculation fields


For every rule mention:

- Rule
- Evidence
- Confirmed or Inferred
- Business impact


----------------------------------------------------


5. DO NOT HALLUCINATE

Do not create:

- Missing workflows
- Missing screens
- Missing approvals
- Missing integrations

If information is unavailable:

Mention:

"Requires additional analysis from code/screenshots/documents"
